Detailed Description

Load, save, release, and dirty-query for the CoreRules in-memory data.

Three load / save overloads, mirroring the pattern from the original CoreRules.dll:

  • LoadDatabases() – registry-based on Windows; falls back to ~/.config/corerules.cfg on Linux.
  • LoadDatabases(const char* pINI) – explicit INI path, same key layout as the registry.
  • LoadDatabases(const char* pCD, const char* pBase) – explicit pCD (read-only, e.g. CD-ROM root) and pBase (writable user data root). Per-subdir fallback: pBase/<dir> first; pCD/<dir> if missing.

After a successful Load, the per-type Record globals are populated (CoreRules::Class_Record, CoreRules::Monster_Record, ... etc.). Consumers read/mutate via those globals. SaveDatabases writes back to the user-side paths; never touches base files. ReleaseDatabases frees all in-memory data and nulls the globals.

Canonical work-unit
LoadDatabases(...);
// ... do work, optional intermediate SaveDatabases() ...
SaveDatabases(...); // final flush
ReleaseDatabases(); // free everything

Returns true on success, false on failure (missing required dirs, parse errors, etc.).
